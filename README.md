## 什么叫静态家宽 IP，贵在哪

静态住宅 IP 是民用宽带运营商分配给家庭用户、在租期内固定不变的 IPv4 地址。判断一个 IP 属于哪类，平台主要看 ASN 和网络名称，不看速度。

打开 `ipinfo.io/json`，重点看三个字段：

- **org**：包含 ASN 和网络名。显示 `AS7018 AT&T Services`、`AS7922 Comcast Cable` 这类，通常属于住宅；显示 `AS14061 DigitalOcean`、AWS、Azure，属于机房。
- **hosting**：返回 `true` 是很强的机房信号。
- **type**：`isp` 表示运营商，`hosting` 表示数据中心。

贵的原因在供给端。机房 IP 段可以批量申请，住宅 IP 只能通过真实的家庭宽带线路接入，或者从运营商手里租已经分配给住户的地址。一条线路能分出来的 IP 数量极少，卖完就得去拉新宽带，交付周期以周计。SixtyNet 四个住宅规格长期 0 Available，就是这个原因造成的，不是营销手段。

## 四步验真：怎么确认买到的是真家宽

单看一个检测站的结果不够。不同站点背后的 IP 数据库不同，同一台机器在 A 站显示家宽、在 B 站显示机房的情况很常见。按下面四步交叉验证，比只看一个分数靠谱。

**第一步，ipinfo.io/json**。看上面说的 `org`、`hosting`、`type` 三个字段。`hosting: false` 加 `type: isp` 是基础门槛，但不构成充分证据。

**第二步，Scamalytics**。看风险分和 `is_datacenter` 标记。分数低不代表就是家宽，只代表这个 IP 暂时没进滥用名单。

**第三步，多库交叉**。常用的几个站各有侧重：

- `ping0.cc`：是不是家庭宽带、是否原生 IP、风控值、同 IP 共享人数
- `ippure.com`：IP 纯净度、定位与运营商、WebRTC 和 DNS 泄露检测
- `ipsuper.com`：汇总多个数据库的结果，含风险系数、原生识别、机房/家宽、ASN
- `ip.net.coffee`：访问不同网站时实际走的出口 IP，用来确认分流规则有没有按预期生效

**第四步，目标平台实测**。前面三步都过了，最后还得看你要用的那个平台认不认。同一品类不同 IP 段的结果可能完全相反：有的美国家宽段 Netflix、TikTok、ChatGPT 全绿，Claude 就是过不去；换一个运营商又反过来了。别人的解锁清单只能当参考，自己拿目标账号试一次才算数。

还有一点要注意：检测站显示的不是住宅 IP，不一定是配置错了。有些站是通过别的域名接口识别 IP 的，只让站点本身走住宅出口不一定够，直接在站内输入 IP 查询更准。

## 静态家宽和动态 NAT 差在哪，什么时候该买便宜的

同样挂「美国住宅 IP」的名头，价格能差六倍。以公开信息里的两个参照产品为例：某家的美国 Frontier 静态家宽 ¥149/月，2vCPU / 2GB / 25GB SSD / 100Mbps / 2000GB 双向；同一家的动态 NAT 是 ¥24/月起，1vCPU / 512MB / 8GB SSD / 1000GB 双向，IP 每天 0 点（UTC+8）更换。

差价买的是「独享」和「固定」这两件事。

静态家宽给你一条独占的固定住宅 IPv4，从开通到到期不变、不共享。养号、注册、支付验证、账号矩阵管理这些需要稳定身份的场景，只能靠它。

动态 NAT 是共享出口，同一个 IP 背后可能挂着好几个人，每天定时更换。便宜是因为成本被摊薄，代价是 IP 不固定、可能被同 IP 的其他人连累，不适合长期养号。临时跑个脚本、做一次性的数据采集，用它够了。

预算紧张又要养号的话，宁可等静态补货，也别拿动态 NAT 去养重要账号。被风控标记之后换 IP 是可以，但账号本身回不来。

## 买完怎么接：VPS 一跳，还是代理链式

住宅 IP 有两条技术路线，选错了会多花很多时间。

**路线一：直接买 IP 是住宅的 VPS。** SixtyNet 走的就是这条。机器本身就是住宅出口，在上面装个服务端，客户端订阅过来就完事，整条链路只有一跳。不需要前置节点，不需要写脚本，也不会出现「主站走住宅、登录接口走机房」这种 IP 来回跳的问题。

**路线二：买纯代理 IP，自己做链式。** 后台只给主机、端口、账号、密码，协议是 SOCKS5 或 HTTP。这类代理不能从国内直连，协议本身也不加密，必须挂在一个前置节点后面。用 mihomo 内核的客户端（Clash Verge Rev 等）可以在订阅的扩展脚本里加一段配置，把住宅节点通过 `dialer-proxy` 指向前置组，这一行就是链式代理。

如果你走路线二，有三个坑要避开：

- **不要直接编辑订阅文件。** 订阅每次更新都会重新下载，改了会被覆盖。用「扩展脚本」，它在订阅更新后自动叠加。
- **不要用「全局扩展脚本」。** 那个会作用到你所有的订阅。
- **同一个服务别拆成两个出口。** 主站走住宅 IP、登录接口走机房，对方看到同一个账号的 IP 来回跳，比完全不用住宅 IP 更糟。

链式代理的性能代价有测评记录：新建连接耗时从约 1.07 秒升到约 1.87 秒，是原来的 1.6 到 2.2 倍；同一个 50MB 文件的下载速度从 2.85 MB/s 变成 2.94 MB/s，基本没差别；RTT 从 135ms 涨到 275ms，多约 140ms。实际感受是首屏慢一点，传输阶段不受影响。视频、下载、系统更新这类大流量留在原来的节点上就行，没必要都绕一圈。

所以对多数人来说，路线一更省事。只有当 SixtyNet 补不到货，或者你已经有现成的前置节点想复用，路线二才值得折腾。
